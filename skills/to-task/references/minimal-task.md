# 最小任务 Markdown 示例

本例对应[主文件](../SKILL.md#54-本地结构化数据tasksjson)中的单任务 JSON。
实际保存位置为 `project-root/task-plan/export-feedback/001-export-failure-feedback.md`，
同目录另存轻量索引和完整 JSON。无需启用需求映射、验收 ID 或计划修订。
示例中的索引链接是生成后相对于任务文件的链接，不是本参考文件的链接。

```markdown
# EXP-001：完善 CSV 导出失败反馈

计划入口：[任务索引](index.md)

- 类型：implementation
- 优先级：P2
- 状态：pending
- 前置依赖：无

## 目标

下载失败时用户能看到错误，不会误以为导出成功。

## 范围与范围外

- 范围：处理现有导出流程的失败反馈。
- 范围外：修改导出字段和登录方式。

## 输入与输出

- 输入：用户要求“导出失败时显示错误提示”；项目现有导出交互和错误反馈约定。
- 输出：页面反馈变更及针对性验证。

## 参考资料

本例未提供独立 PRD、SPEC 或设计文档，来源为上述用户要求，`references` 为 `[]`。
实际任务有文档时，在此列出可点击的路径或链接、相关章节及内容摘要。

## 约束

沿用现有接口和登录流程。

## 验收与验证

| 完成条件 | 检查方式 |
| --- | --- |
| 下载失败显示可读错误，且不显示下载成功。 | 模拟导出失败，检查错误提示及成功提示互斥。 |

## 未决问题与假设

无。尚未执行验证，没有执行证据。
```
