# PostgreSQL 物理设计参考

本文件用于目标数据库为 PostgreSQL 时读取。生成 DDL 前应确认 PostgreSQL 主版本、扩展、排序规则、时区、连接池和迁移工具。

## 1. 主键与 Identity

- 常规实体主键默认评估 `BIGINT GENERATED BY DEFAULT AS IDENTITY`。
- 若不允许普通 INSERT 显式覆盖生成值，可评估 `GENERATED ALWAYS AS IDENTITY`。
- Identity 依赖隐式 sequence 生成值，但 Identity 本身不替代 PRIMARY KEY/UNIQUE 约束。
- 不将 `SERIAL` 作为新项目首选；新设计优先评估 Identity。
- PostgreSQL 没有原生 UNSIGNED 整数类型，`BIGINT` 是有符号 64 位整数。跨数据库项目应采用可映射的正数范围。

示例：

```sql
CREATE TABLE lottery (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name VARCHAR(128) NOT NULL,
    status SMALLINT NOT NULL DEFAULT 0,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
);

COMMENT ON TABLE lottery IS '抽奖活动表';
COMMENT ON COLUMN lottery.id IS '主键 ID';
COMMENT ON COLUMN lottery.name IS '抽奖活动名称';
COMMENT ON COLUMN lottery.status IS '活动状态：0-未开始，1-进行中，2-已结束';
COMMENT ON COLUMN lottery.created_at IS '创建时间';
COMMENT ON COLUMN lottery.updated_at IS '最后修改时间';

CREATE INDEX idx_lottery_status ON lottery (status);
```

`updated_at` 默认值只处理 INSERT，不会在 UPDATE 时自动改变。应统一由应用维护，或明确使用触发器维护。

## 2. UUID

- PostgreSQL 有原生 `uuid` 类型，可存储不同版本的 UUID。
- PostgreSQL 18 提供 `uuidv7()` 时间有序 UUID 生成函数；较早版本不能假设该函数可用。
- 若数据库版本不支持内置 UUIDv7，可由应用生成或采用经过验证的兼容方案。
- UUIDv4 是随机型；UUIDv7 是时间有序型。根据索引写入模式、键宽和跨系统要求选型。
- 128 位 UUID 与 64 位整数相比具有更宽的索引键；需要评估存储、缓存及关联索引成本。

## 3. 时间与时区

- `TIMESTAMP WITH TIME ZONE`（`timestamptz`）适合表达真实时间点。PostgreSQL 以时间点语义处理，输出时按会话时区显示；它不保留最初输入的时区名称。
- `TIMESTAMP WITHOUT TIME ZONE` 适用于不代表全球唯一时间点的本地日期时间。
- `DATE` 用于纯日期。
- `timestamptz` 的精度默认可到微秒；项目应明确统一精度。
- `CURRENT_TIMESTAMP` 在事务开始时确定；需要语句时间或实际墙钟时间时，应理解 `statement_timestamp()` / `clock_timestamp()` 的语义差异。
- 涉及当地日历规则时，另外保存 IANA 时区标识。

## 4. 数据类型与约束

- 精确金额用 `NUMERIC(p,s)`；不要用 `real` / `double precision` 记账。
- PostgreSQL `boolean` 是原生布尔类型。
- `jsonb` 常用于需要查询或索引的 JSON 数据；仍不得用它替代核心关系模型。
- 可按业务评估 CHECK、部分唯一索引、表达式索引、GIN、GiST、BRIN 等特性。
- 外键、约束验证及在线索引操作的语法和锁行为应按具体版本确认。

## 5. 索引与 DDL 风险

- B-tree 多列索引通常优先利用前导列的约束；按查询谓词、排序和数据分布验证列顺序。
- `CREATE INDEX CONCURRENTLY` 可用于降低普通建索引对并发读写的阻塞，但有事务块限制、失败残留索引及额外资源成本，不能不加评估地机械使用。
- 通过 `EXPLAIN (ANALYZE, BUFFERS)` 分析计划和缓冲区行为；`ANALYZE` 会执行语句，修改型语句须在安全环境使用。
- 修改表结构前评估锁级别、表重写、约束验证、长事务和复制延迟。
