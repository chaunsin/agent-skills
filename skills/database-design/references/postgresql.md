# PostgreSQL Physical Design

Confirm the major version, extensions, collation, time zone, connection pool, and migration tools before generating DDL. Evaluate `BIGINT GENERATED BY DEFAULT AS IDENTITY` for ordinary keys, or `GENERATED ALWAYS` to restrict explicit values. Identity uses a sequence and does not itself enforce uniqueness; add a primary or unique constraint. Prefer evaluating identity over `SERIAL` in new designs. PostgreSQL `BIGINT` is signed; use a compatible positive range across databases.

```sql
CREATE TABLE lottery (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name VARCHAR(128) NOT NULL,
    status SMALLINT NOT NULL DEFAULT 0,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
);
COMMENT ON TABLE lottery IS 'Lottery';
COMMENT ON COLUMN lottery.id IS 'Primary key';
COMMENT ON COLUMN lottery.name IS 'Lottery name';
COMMENT ON COLUMN lottery.status IS 'Status: 0 pending, 1 active, 2 ended';
COMMENT ON COLUMN lottery.created_at IS 'Creation time';
COMMENT ON COLUMN lottery.updated_at IS 'Last update time';
CREATE INDEX idx_lottery_status ON lottery (status);
```

The `updated_at` default applies on insert only; maintain it consistently in the application or an explicit trigger.

PostgreSQL's native `uuid` stores various UUID versions. PostgreSQL 18 provides `uuidv7()`; earlier versions may require an application generator or verified alternative. Compare UUIDv4 and UUIDv7 locality and 128-bit key costs against requirements.

`timestamptz` represents an instant, displays it in the session zone, and does not retain the original zone name. Use `timestamp without time zone` for local date-times that are not global instants, and `date` for dates. Standardize precision; store an IANA zone for calendar rules. `CURRENT_TIMESTAMP` is fixed at transaction start; assess `statement_timestamp()` or `clock_timestamp()` where appropriate.

Use `NUMERIC` for exact money, native `boolean` for flags, and `jsonb` where flexible JSON queries justify it, not in place of core relations. Assess CHECK, partial or expression indexes, GIN, GiST, and BRIN by workload. Verify constraint validation and locking against the deployed version. Validate B-tree column order using query predicates and plans. `CREATE INDEX CONCURRENTLY` reduces blocking but has transaction restrictions, failure remnants, and resource costs. `EXPLAIN (ANALYZE, BUFFERS)` executes the statement; use a safe environment for writes. Assess locks, table rewrites, long transactions, and replication lag before DDL.

Use the deployed version's manual.
