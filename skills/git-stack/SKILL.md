# Git 工作流

按照用户要求执行 Git 操作，并保留无关工作。开始前读取适用的仓库指令和提交规范。
用户指令优先于仓库约定和本技能；已经获得授权的操作，无需重复询问。

## 适用方式

- 本技能适用于不同 agent、编辑器、操作系统、Git 托管服务及项目技术栈。
  根据当前能力选择 Git CLI、Git API 或宿主提供的等效工具，不以某个插件、终端或平台功能为前提。
- 命令展示需要确认的 Git 状态，不要求逐条照搬执行。优先利用已有结果，按任务范围读取差异；
  路径、引用、引号和变量语法按实际 shell 或工具调整。
  示例中的 `<...>` 均需替换为实际值；选项不可用时使用兼容方式获取等效信息。
- 验证项目、工作区准备方式及提交粒度由用户目标和仓库规范决定。
  本技能使用中文说明，不限定项目语言、提交信息语言、分支命名或固定提交格式。

## 快速参考

1. 确认仓库、当前引用及操作目标，再检查任务需要的工作树状态。
   可用 `git rev-parse --git-dir` 识别仓库；工作树中的 `.git` 可能是文件。
   裸仓库没有工作树，仍可执行适用的引用和推送操作；尚无首个提交的仓库也不属于异常。
   仅在任务依赖的仓库或访问能力不可用时，报告相应阻塞项。
2. 涉及工作树更改时，分别检查已暂存、未暂存和未跟踪的内容。保留无关工作，结合会话上下文确认范围，
   仅在是否纳入某项更改尚不明确时询问用户。
3. 运行检查前先盘点已有验证结果。复用仍适用的结果，仅预检待执行检查需要的环境，
   并按照[验证规则](validation.md)分类处理失败。仓库强制门禁和钩子仍然适用。
4. 仅执行已授权的提交、推送、冲突处理或工作区操作，报告最终版本、目标位置和验证边界。

用户仅要求提交时，不得据此推断其已授权创建远端审查请求、标签、发布版本或执行推送。

## 护栏

- 不将修改 Git 配置作为默认前置步骤；确需调整时，限定在已有授权和所需作用域内。
  不丢弃无关更改，不在核对内容前暂存整个工作树。
- 丢弃更改、历史重写、强制推送及跳过钩子等操作需要明确授权，并遵守宿主安全限制和远端保护规则。
- 钩子失败时，先分类，再决定修改代码或重跑检查。检查 HEAD 和暂存区，确认是否已经生成提交；
  不将修改已有提交作为自动恢复步骤。
- 未经用户明确授权，不直接读取或输出 SSH 私钥内容；正常 Git 认证使用既有认证机制。
