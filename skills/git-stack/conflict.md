# conflict

当代码合并出现代码冲突时使用此流程

## 流程

1. 查看合并/变基的**当前状态。检查 Git 历史记录和冲突文件。**
2. **找出每起冲突的根本原因**。深入了解每次更改的原因及其最初意图。阅读提交信息，查看 PR，查看原始问题/工单。
3. **相关领域可用的SKILL以及CLI工具。** 比如drizzle SQL迁移文件产生冲突即利用对应的技能或工具解决对应冲突。
4. **逐个解决每个代码块的问题。** 尽可能保留双方的意图。如果存在冲突，则选择符合合并目标的那个，并注意权衡取舍。不要**创造**新的行为。始终解决；绝不`--abort`……
5. 运行编译、代码检查和相关测试。
6. **完成合并/变基操作。** 暂存所有更改并提交。如果是变基操作，则继续变基过程，直到所有提交都完成变基。

## 护栏

- [ ] 任何文件不能留下冲突标记
- [ ] 解决冲突时，避免进行大规模重构, 以及新需求、功能开发。
- [ ] 解决冲突的专项skill或CLI工具，只能修改对应职责范围内的内容，不能修改其他。

## 输出报告

> 注意：以下报告内容要完整，可嵌入整体报告对应位置呈现。

- **冲突原因**: 源分支重构了计算逻辑，目标分支修复了边界条件bug。
- **解决方式**: 结合两者，保留重构后的逻辑，并整合bug修复。
- **风险点**: 需确认单元测试覆盖新老逻辑，避免回归。
