# commit

从当前工作树、工作区更改中创建一个精心编写的单个 git 提交 + 可选的推送。

> 注意: 代码工作区干净，无任何修改，则直接退出。

## 明确操作范围

1. 暂存区是否存在未提交未被追踪的代码 `git diff HEAD` 如存在则**提示**用户是否包含这些代码提交。
2. 哪个分支 `git branch --show-current`. 哪个worktree
3. 是否需要切换分支

## 提交格式

```text
<type>(<scope>,...): <sample description>

[可选正文]

[可选的脚注]
```

- **type**: 提交类型，常用类型 feat、fix、docs、style、refactor、ci、chore、perf等
- **scope**: 影响模块或文件，多个以逗号分割。
- **description**: 本次提交核心简短描述
- **可选正文**: 列表形式呈现，描述具体修改影响内容
- **可选脚注**: 标记破坏性变更（BREAKING CHANGE）或关联 Issue（如 `Closes #123`）

**避免提交反模式：**

- 解决冲突，conflict
- fix bug
- 111、222、. 、，...，。。。。
- update、更新
- add、添加
- 下班

## 提交流程

1. 代码必须编译通过，以及lint、format、typecheck等代码质量工具检测。
2. 代码必须通过测试。
3. 分析现有代码影响文件与差异并生成提交信息，遵从 **提交格式**。
4. 查询当前仓库代码状态，以及分支，如果存在新代码提交则先拉取代码，如果存在代码冲突问题，则先解决冲突问题，解决完冲突之后则提交代码
5. 确认提交结果是否包含主题信息 `git status`

识别用户输入的提示词代码提交意图，如果用户明确指名提交并推送代码到云端分支，则直接提交**不向用户发起push询问** , 但需要生成推送报告:

```text
我已把本地分支[local branch]提交(commit),并推送(push)到了远端分支[remote branch]
```

反之意图模糊、不明确、未提及，则需要向用户发起**询问授权**，提示模板如下:

```text
是否推送本地分支[local branch]到远端仓库[remote branch]?

A: 推送
B: 取消，暂不提交。
```

## 常见问题

| 情况与问题 | 方案 |
| ------------------------------------------ | ----------------------------------------------------- |
| 编译、测试未通过、lint、format、typecheck等代码质量工具检测没通过 | 立即停止提交，修复对应问题然后再执行提交流程操作 |
| 代码提交出现冲突 | 立即停止提交，处理完冲突并测试通过后在执行后续提交操作。冲突处理可参考`./conflict` 章节内容。 |
| 在授权推送代码情况下，推送代码出现网络失败 | 采用最大重试3次策略，仍然失败后则给出提示。 |

## 危险操作

- [ ] 用户未明确说明push推送代码，却执行了push操作，应该采用询问授权方式交给用户。
